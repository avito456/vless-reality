# xrayadm

Консольная программа на Mac для управления клиентами Xray VLESS+Reality на VPS по SSH:
добавление и удаление клиентов, ссылки и QR, статистика трафика, бэкап и откат конфига.
Клиенты добавляются и удаляются через Xray gRPC API без рестарта (активные сессии не рвутся)
и одновременно записываются в `/usr/local/etc/xray/config.json`.

## Требования
- macOS/Linux, [uv](https://docs.astral.sh/uv/)
- доступ к серверу по SSH-ключу (без пароля): `ssh -p PORT USER@HOST` (адрес задаётся в `.env`, см. ниже)
- на сервере: Xray с inbound с тегом `vless-reality` (так сделано в инструкции)

## Запуск
Из каталога проекта:

    uv run xrayadm            # текстовое меню
    uv run xrayadm <команда>  # одна команда без меню

При первом запуске `uv` сам создаст окружение и поставит зависимости.
Чтобы запускать из любого каталога: `uv tool install /Users/ev/workspace/shadowsoks`,
затем просто `xrayadm`.

## Настройка адреса сервера (.env)
Адрес SSH-подключения хранится в файле `.env` (он в `.gitignore`, в git не попадает):

    cp .env.example .env
    # отредактируйте .env

```
XRAYADM_HOST=1.2.3.4   # обязательно: IP или имя сервера
XRAYADM_PORT=22        # SSH-порт, по умолчанию 22
XRAYADM_USER=root      # SSH-пользователь, по умолчанию root
```

`.env` ищется в текущем каталоге, затем в `~/.config/xrayadm/.env` (удобно после
`uv tool install`, когда программа запускается из любого каталога). Переменные,
заданные в окружении, приоритетнее файла: `XRAYADM_HOST=5.6.7.8 uv run xrayadm`.
Без `XRAYADM_HOST` программа завершится с понятной ошибкой.

## Новый сервер: первая установка
Если после подключения на сервере не найден Xray (нет бинаря `xray` или `config.json`,
либо конфиг пустой), при запуске меню программа напишет «VLESS (Xray) на сервере не найден»
и предложит установить. Та же установка запускается командой:

    uv run xrayadm install            # с вопросами
    uv run xrayadm install --yes      # без вопросов: порт 443, SNI www.microsoft.com, клиент client1
    uv run xrayadm install --port 8443 --sni www.cloudflare.com --email phone

Что делает установка (под root по SSH-ключу):
1. проверяет, что порт свободен (и не совпадает с SSH-портом);
2. ставит Xray официальным скриптом [XTLS/Xray-install](https://github.com/XTLS/Xray-install)
   (серверу нужен доступ к GitHub; при отсутствии `curl` ставит его через apt/dnf/yum);
3. генерирует ключи x25519 и shortId, собирает конфиг VLESS+Reality (flow `xtls-rprx-vision`)
   с уже включённым gRPC API и статистикой — отдельный `bootstrap` не нужен;
4. открывает порт в `ufw` или `firewalld`, если фаервол активен (SSH-порт не трогает);
5. включает BBR (`/etc/sysctl.d/99-bbr.conf`); если ядро не поддерживает — пропускает;
6. записывает конфиг (с проверкой `xray run -test`), включает автозапуск и перезапускает xray;
7. создаёт первого клиента и показывает `vless://` ссылку и QR.

Если Xray уже настроен, но inbound `vless-reality` в нём нет, установка **не запускается**:
чужой конфиг программа не перезаписывает. Повторный запуск на настроенном сервере ничего не меняет.
Автопроверка выполняется только при запуске меню; остальные команды работают как раньше.

## Первый запуск: включение API (для серверов, настроенных вручную) (один раз)
Пока в конфиге нет API, добавление и удаление работать не будут (просмотр, ссылки и бэкапы — будут).

    uv run xrayadm bootstrap --yes     # или пункт 8 меню

Команда включает API на `127.0.0.1:10085` и счётчики трафика. Это **один рестарт xray**:
подключения клиентов на несколько секунд оборвутся и переподключатся. Перед правкой
делается бэкап, и если xray не стартовал, конфиг возвращается автоматически.
Если ваш Mac ходит через этот же VPN, SSH-сессия может на секунды прерваться — это нормально,
программа опрашивает сервер заново до 90 секунд.

## Меню
```
  1. Список клиентов
  2. Добавить клиента
  3. Удалить клиента
  4. Ссылка / QR клиента
  5. Статистика трафика
  6. Создать бэкап конфига
  7. Откатить конфиг из бэкапа
  8. Включить API (bootstrap, один рестарт xray)
  0. Выход
```
Клиента для удаления, ссылки и откат выбирают по номеру из списка, `0` — отмена.
Удаление, откат и bootstrap просят подтверждение.

## Типовые сценарии
**Добавить устройство.** Пункт 2, введите имя (латиница, цифры, `.` `_` `-`, например `pixel`).
Программа покажет `vless://` ссылку и QR-код. Отсканируйте QR или вставьте ссылку в клиент
(v2rayN, v2rayNG, Streisand, FoXray, V2Box). Ссылку можно показать позже: пункт 4.
Один клиент — одно устройство: так видно, кто сколько трафика расходует.

**Удалить устройство.** Пункт 3, выберите номер, подтвердите. Клиент отключается сразу.

**Посмотреть трафик.** Пункт 5. Счётчики считаются с последнего рестарта xray; при показе
можно сбросить их. Клиент появляется в таблице после первого трафика.

**Что-то сломалось.** Пункт 7 (или `xrayadm rollback --yes`) возвращает последний бэкап и
перезапускает xray.

## Команды без меню
| Команда | Что делает |
|---|---|
| `xrayadm list` | клиенты из конфига |
| `xrayadm add <имя> [--no-qr] [--params]` | добавить клиента, показать ссылку и QR |
| `xrayadm remove <имя>` | удалить клиента |
| `xrayadm link <имя> [--no-qr] [--params]` | ссылка и QR существующего клиента |
| `xrayadm stats [--reset]` | трафик по клиентам |
| `xrayadm backup` / `backups` | создать бэкап / показать список |
| `xrayadm rollback [путь] --yes` | вернуть бэкап (по умолчанию последний), рестарт xray |
| `xrayadm install [--yes] [--port] [--sni] [--email]` | установить Xray и VLESS+Reality на новый сервер |
| `xrayadm bootstrap --yes` | включить API (один рестарт) |

## Безопасность и бэкапы
- Перед каждой записью на сервер делается копия в `/usr/local/etc/xray/backups/`
  (`config.ГГГГММДД-ЧЧММСС.json`, хранятся 20 последних).
- Новый конфиг проверяется `xray run -test` и заменяется атомарно; при ошибке на сервере
  остаётся прежний.
- Если применить изменение через API не удалось, конфиг восстанавливается из бэкапа.
- Приватный ключ Reality остаётся на сервере; публичный ключ для ссылки вычисляется там же.
- Ссылки содержат UUID клиента — это его пароль, не публикуйте их.
- Нельзя удалить последнего клиента.

## Разработка
    uv run pytest

Структура: `xrayadm/config.py` (чистая логика над конфигом), `server.py` (операции на хосте),
`links.py`, `stats.py`, `cli.py` (команды), `menu.py` (меню), `ssh.py` (обёртка над `ssh`).

## Если что-то не работает
| Симптом | Причина / решение |
|---|---|
| `Permission denied` / зависание на SSH | нет входа по ключу: проверьте `ssh -p PORT USER@HOST` с значениями из `.env` |
| `XRAYADM_HOST is not set` | создайте `.env` из `.env.example` |
| `port N is already in use` при установке | порт занят другим сервисом: выберите другой `--port` |
| установка зависла/упала на скачивании | серверу нужен доступ к github.com; проверьте `curl -I https://github.com` на сервере |
| `API not enabled` | выполните `bootstrap --yes` |
| клиент добавлен, но не подключается | проверьте, что в приложении `flow=xtls-rprx-vision` и `sni`/`pbk`/`sid` взяты из ссылки без правок |
| `xray not active ... after restart` | смотрите `journalctl -u xray -n 50` на сервере, затем `rollback --yes` |
